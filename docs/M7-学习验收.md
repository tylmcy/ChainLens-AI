# M7 RAG 知识库学习验收

自动测试通过只说明实现满足当前契约，不代表你已经掌握 RAG。请亲自完成以下任务，并能用自己的话解释每一步。

## 必须能解释

- 为什么向量检索是在找“语义相近”，不是在数据库里做关键词包含查询。
- 为什么 CHAIN 来源能证明本笔交易事实，而 KNOWLEDGE 来源只能解释概念。
- 为什么 `available=false` 与 `available=true, hits=[]` 不能混成同一种结果。
- 为什么稳定 chunk ID、contentHash 和事务回滚能让重复同步保持可预测。

## 必须能独立操作

1. 在 `docs/knowledge/` 新增一篇符合 front matter 契约的中文文档，并让 `KnowledgeCorpusTest` 通过。
2. 连续执行两次同步，解释第二次为什么主要是 `unchanged`，再修改一个段落并观察 `updated`。
3. 运行 `-P rag-eval`，读懂逐例 JSON 与 Markdown 汇总，并解释 top-3 命中率。
4. 分别关闭 RAG、停止 PostgreSQL、提供错误模型路径，说明三个故障在日志和 API 中有什么差别。

## 学习完成标准

你能不照抄 README，独立完成上述操作；能改一篇文档、预测同步统计；能指出一次检索误命中的可能原因，并知道该调知识内容、切块还是相似度阈值。完成前，M7 的“工程实现完成”和“个人掌握完成”应分开记录。
