# M8 MCP Server 学习验收

自动测试通过只说明当前代码满足契约，不代表你已经掌握 MCP。请亲自完成下面的解释、连接和排错。

## 必须能解释

- Streamable HTTP `/mcp` 为什么不等于 `POST /api/v1/analyses` 的业务 SSE。
- 五个工具为什么都可以声明为只读，以及 MCP 分析为什么是 `persisted=false`。
- DeepSeek Harness 本地模式为什么选 stdio，而 Inspector/Cursor 本地联调为什么优先选 Streamable HTTP。
- 为什么 `CHAIN` 可以证明当前交易事实，`KNOWLEDGE` 只能解释概念。
- 为什么 Bearer Token 不等于 TLS、OAuth 或可公网部署。

## 必须能独立操作

1. 只看 README，用 MCP Inspector 连接 `/mcp`，列出且说出五个工具各自的边界。
2. 使用 Anvil 的 `unlimited-approval` 调用 `analyzeTransaction`，找到 `ruleId`、`confidence`、`rpcMethod` 和 `jsonPointer`。
3. 按示例配置 DeepSeek Harness stdio，确认它不启动 8080 端口，并调用一次 `resolveSelector`。
4. 传入 `0x1234`，从 `INVALID_INPUT` 独立判断是客户端输入错误，而不是 Docker、RPC 或 LLM 故障。
5. 可选：设置一个未提交 Git 的 `CHAINLENS_MCP_TOKEN`，分别验证无 Token 被拒绝和正确 Token 可连接。

## 学习完成标准

你能不照抄 README 说清上述三种接入的区别，能独立连接一个客户端，并能从稳定错误类别定位一次无效参数。完成前，M8 的“工程实现完成”和“个人掌握完成”应分开记录。
