## 这条规则在说什么

交易回执的 status 为失败，表示 EVM 执行没有完成，合约状态改变和事件日志不会生效。发送者通常仍会支付已经消耗的 gas，因为验证和执行过程确实占用了网络资源。失败不一定代表安全攻击，也可能来自余额或授权不足、滑点限制、截止时间过期、合约主动 revert，或者调用参数不符合要求。ChainLens V1 只根据回执判断成功或失败，不伪造具体 revert 原因。

## 为什么需要留意

连续失败可能说明用户连接了错误网络、使用了过期页面，或调用条件已经变化。如果界面声称操作成功而链上回执失败，应以链上回执为准。失败交易不会产生有效的 ERC-20 Transfer 或 Approval 状态变化；某些 RPC 返回的调试信息可能解释原因，但普通 JSON-RPC 回执并不总包含这些细节。因此报告会把未知原因写入 limitations，而不是根据方法名或输入数据猜测。

## 怎样核对与应对

先比对交易哈希、链 ID、from、to 和回执区块，再检查调用时需要的余额、授权、期限与业务参数。若钱包准备重试，不应机械提高 gas limit 或重复签名，而应先理解失败条件；相同输入在状态变化后可能产生不同结果。开发排错时可以在本地分叉链重放，或使用节点支持的 trace 能力，但这些属于 V1 报告之外的进一步调查。
