## 这条规则在说什么

一笔交易可以在执行过程中产生多条 ERC-20 Transfer 事件。批量分发、空投、路由兑换、清算和资金归集都可能产生许多转移，因此数量本身不是恶意证据。ChainLens 使用固定阈值做启发式提醒，并以成功解析的 Transfer 日志数为准。规则关注的是“值得进一步查看的复杂度”，不会根据事件数量自动给地址贴上诈骗标签。

## 为什么需要留意

转移数量越多，人工核对每个 token、参与地址和金额越困难，也更容易忽略夹杂其中的异常流向。某些攻击和资金拆分会制造复杂事件，但正常的聚合器同样可能如此。事件还可能包含垃圾代币或刻意模仿名称的代币，所以展示名称不能替代合约地址。报告中的严重级别与置信度由确定性规则给出，知识检索只能解释其含义，不能自行升级或降级。

## 怎样核对与应对

按 token 合约分组查看 Transfer，区分用户直接相关的流入流出与协议内部路由，再核对净变化。重点检查陌生合约、零地址、风险列表命中和异常大的原始数值。不同代币 decimals 不同，rawValue 不能直接横向比较；V1 保留原始整数而不擅自换算。若需要完整资金流图，应使用专门的追踪工具，这超出单笔 V1 报告范围。
