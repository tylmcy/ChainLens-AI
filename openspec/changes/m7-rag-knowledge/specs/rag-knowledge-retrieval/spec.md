# Spec Delta

## Purpose

定义 ChainLens 如何从仓库内受控知识资料构建可追溯的本地向量知识库，为风险解释和术语说明提供依据，同时确保知识内容不能替代 Ethereum JSON-RPC 事实或确定性规则结论。

## ADDED Requirements

### Requirement: 知识资料受控且可追溯
系统 SHALL 只摄取仓库内已审核的 Markdown 知识资料，并为每个检索片段保留来源文件、标题、内容哈希和关联 ruleId；知识资料不得包含秘密或被当作链上事实来源。

#### Scenario: 摄取规则解释文档
- **WHEN** 一份合法知识文档包含标题、正文和关联 ruleId
- **THEN** 系统生成的每个片段都可追溯到原文件、标题、内容哈希和该 ruleId

#### Scenario: 文档缺少必要元数据
- **WHEN** 知识文档缺少标题、来源标识或声明的 ruleId 格式无效
- **THEN** 系统拒绝该文档并给出明确校验错误，不将不完整片段写入知识库

### Requirement: 确定性切块并幂等同步知识库
系统 SHALL 按 Markdown 标题边界和稳定规则生成 300～500 个中文字符为主的片段，通过稳定内容哈希幂等写入知识库，并移除本次受管知识集中已经删除或被替换的旧片段。

#### Scenario: 重复同步未变化的知识资料
- **WHEN** 同一版本知识资料被连续同步两次
- **THEN** 第二次同步不产生重复片段，并报告新增、更新、删除和未变化数量

#### Scenario: 修改或删除知识段落
- **WHEN** Git 管理的知识内容被修改或删除后重新同步
- **THEN** 系统写入新片段并清理对应旧哈希，检索结果不再返回过期内容

#### Scenario: 单个文档解析失败
- **WHEN** 同步过程中有文档无法解析或嵌入
- **THEN** 系统报告失败来源且不得把半成品片段标记为本轮同步成功

### Requirement: 返回有界且带来源的相关知识
系统 SHALL 对中文查询返回最多 3 个超过配置阈值的知识片段，每个命中包含正文、来源文件、标题、关联 ruleId 和相似度；系统 MUST 区分“可用但无匹配”与“知识库不可用”。

#### Scenario: 查询命中相关规则解释
- **WHEN** 用户查询“无限授权为什么危险”且对应知识已同步
- **THEN** top-3 结果包含无限授权解释片段及其来源、关联 ruleId 和相似度

#### Scenario: 查询没有足够相关的内容
- **WHEN** 所有候选片段都低于相似度阈值
- **THEN** 系统返回可用状态和空命中列表，不编造知识答案

#### Scenario: 向量存储或嵌入模型不可用
- **WHEN** 查询时无法访问向量存储或嵌入模型
- **THEN** 系统返回不可用状态和可诊断原因，交易分析主链路仍可继续

### Requirement: 支持启动同步和受限手动同步
系统 SHALL 在显式启用 RAG 时于应用启动后同步受控知识；手动同步入口 MUST 仅在本地管理配置显式启用时存在，并返回同步统计而不接受任意文件路径或 URL。

#### Scenario: 默认未启用嵌入模型
- **WHEN** 应用使用默认配置启动且未启用 RAG
- **THEN** 应用不下载模型、不连接向量表，并保持确定性分析能力可用

#### Scenario: 首次启用本地 RAG
- **WHEN** 应用启用本地嵌入且模型尚未缓存
- **THEN** 系统下载并缓存配置的模型资源，失败时将知识能力标记为不可用但不阻止应用提供确定性分析

#### Scenario: 调用手动同步入口
- **WHEN** 本地管理配置已启用且调用者请求重新同步
- **THEN** 系统只处理预配置的仓库知识目录，并返回新增、更新、删除、未变化和失败统计

#### Scenario: 手动同步入口未启用
- **WHEN** 应用未启用本地知识管理配置
- **THEN** 手动同步入口不可访问

### Requirement: 可重复评测检索质量
系统 SHALL 提供 10～15 条版本化中文查询用例，以预期来源或 ruleId 是否出现在 top-3 计算命中率，并记录模型、数据集版本和阈值。

#### Scenario: 运行离线检索评测
- **WHEN** CI 使用固定知识资料、固定模型和固定查询集执行评测
- **THEN** 系统输出逐例结果与汇总 top-3 命中率，命中率低于 90% 时评测失败
